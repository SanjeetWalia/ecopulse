# v5 setup: what to run, in order

Branch `v5-growth`. Nothing here is needed for build 19 (v4); do these when
you're ready to test v5 against the real backend. Until then the v5 build
runs on sample data (`EXPO_PUBLIC_SAMPLE_MODE` unset).

## 1. Database

```bash
cd ~/Documents/Ecopulse/ecopulse
git checkout v5-growth
supabase db push              # applies 0007_v5_growth.sql (additive only)
```

Then run `supabase/run-once/2026-09-27-v5.sql` in the SQL editor, step by step.
Step 2 (grandfather current testers for a year) is optional; skip it if you
decide against it.

## 2. Functions

```bash
supabase functions deploy analyze-snap
supabase functions deploy recall-sync --no-verify-jwt
supabase functions deploy revenuecat-webhook --no-verify-jwt
supabase secrets set REVENUECAT_WEBHOOK_SECRET=<long random string>
# optional: supabase secrets set SNAP_MODEL=<current Sonnet model id>   (default is Haiku)
```

`analyze-snap` is deployed WITH JWT verification: it reads the user from
their session instead of trusting a `userId` in the body.

## 3. App Store Connect

- Subscription group **Eco Pulse**
  - Product `ecopulse_monthly`, $10 a month
  - Introductory offer: **7-day free trial**
  - Promotional offer, identifier **`half_month`**: 1 month, 50% off
    (this delivers a key's half-price month, to both people)
- Consumable `ecopulse_streak_repair`, $0.99
- Generate an In-App Purchase key (for RevenueCat and promotional-offer
  signing).

Check in the sandbox before launch: a promotional offer redeemed during the
7-day trial should apply to the first paid month. If it applies to the month
after instead, change the copy on the paywall and chain screens to say
"a half-price month" rather than "your first paid month".

## 4. RevenueCat

- New project, iOS app with the bundle id, upload the In-App Purchase key.
- Entitlement **`pulse`**, attached to `ecopulse_monthly`.
- Offering **`default`** with a Monthly package → `ecopulse_monthly`.
- Webhook: `https://yzeslhdoviwahtunthor.supabase.co/functions/v1/revenuecat-webhook`,
  Authorization header `Bearer <REVENUECAT_WEBHOOK_SECRET>`.
- Copy the iOS public SDK key.

## 5. Build

In `eas.json`, for the profile you'll build v5 with:

```json
"env": {
  "EXPO_PUBLIC_SAMPLE_MODE": "false",
  "EXPO_PUBLIC_REVENUECAT_IOS_KEY": "appl_…"
}
```

`react-native-purchases` is a native module, so this needs a new EAS build;
it won't run in Expo Go (the app falls back to sample purchases there).

## 6. Before the first real user

- Review the fact library: only rows with `reviewed_at` set are ever shown.
  0007 seeds the beer-packaging facts; every new fact needs a source.
- Heads up digest items (rule changes, testing) are only shown once
  `reviewed_at` is set. Recalls are shown straight from the FDA and USDA.
- Watch the `recall-sync` logs after its first run. The FSIS field names
  couldn't be verified from here; the log line says how many rows parsed.
